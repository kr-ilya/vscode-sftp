# SyncX — SFTP & FTP Sync

**Держит локальную папку и удалённую в согласии, не выходя из VS Code.**

Заливка при сохранении, синхронизация в любую сторону по команде, дерево удалённой стороны и сравнение с ней — по SFTP, FTP/FTPS или в путь на этой же машине.

[**Установить из маркетплейса**](https://marketplace.visualstudio.com/items?itemName=kr-ilya.syncx) · [Релизы](https://github.com/kr-ilya/vscode-sftp/releases) · [Конфигурация](docs/configuration.md) · [Частые вопросы](FAQ.ru.md)

- Заливка при сохранении или по мере изменения файлов
- Синхронизация локально → удалённо, удалённо → локально или в обе стороны, с правилами пропуска, обновления и удаления
- Отправка ровно того, что git считает изменённым
- Дерево удалённых файлов с пометкой, как каждый соотносится с вашей копией
- Несколько удалённых сторон на одну папку: staging, production, промежуточные узлы
- Проверка host key, пароли в SecretStorage

---

## Возможности

**Синхронизация** — Залить или скачать отдельный файл, папку или проект целиком. Отразить локально → удалённо, удалённо → локально или в обе стороны, с правилами что пропускать, что обновлять, что удалять.

**Заливка при сохранении** — `uploadOnSave` отправляет сохранённый файл, `downloadOnOpen` скачивает его при открытии. Вотчер умеет заливать по мере изменения файлов и, если попросить, повторять удаления.

**Дерево удалённой стороны** — Отдельное представление с содержимым удалённой стороны: открыть файл, сразу увидеть, какие из них расходятся с локальными. Любой файл можно сравнить с его удалённой версией.

**Заливка по git** — Отправить всё, что изменилось с последнего коммита, включая переименования и удаления, по `Ctrl+Alt+U`.

**Профили** — Несколько удалённых сторон на одну папку, переключаются из палитры команд. В многокорневом воркспейсе — своя на каждую папку, и поддерево может иметь собственную.

**SSH, FTP и FTPS** — Пароль, приватный ключ, `ssh-agent` или keyboard-interactive; настройки из `~/.ssh/config` подхватываются; соединение может идти через один или несколько промежуточных узлов.

## Почему SyncX

Форк [Natizyskunk/vscode-sftp](https://github.com/Natizyskunk/vscode-sftp), который сам является форком [liximomo/vscode-sftp](https://github.com/liximomo/vscode-sftp). Формат конфигурации не менялся, поэтому существующий `.vscode/sftp.json` работает как есть.

| | Оригинал | SyncX |
| --- | --- | --- |
| **Что запускает заливку** | Любое событие файловой системы, включая событие на каталоге | Событие запускает проверку; перед отправкой сверяется содержимое |
| **Host key** | Принимается молча | Сверяется с `~/.ssh/known_hosts`; изменившийся ключ отклоняется |
| **Пароли** | В файле, который вы коммитите | В SecretStorage, сохраняются только после того, как сработали |
| **Опечатка в `remotePath`** | Деплой уходит туда, куда она указывает | Первая заливка в новый путь спрашивает и показывает, что там уже лежит |
| **Оборванная заливка** | Обрезает удалённый файл | Пишется во временный файл и переименовывается на место |
| **`concurrency: 4`** | Четыре передачи на операцию | Четыре всего |
| **Во время передачи** | Крутящийся индикатор | Переданные байты и кнопка «Отмена» |
| **Недоверенные воркспейсы** | Не объявлены | Объявлены неподдерживаемыми; команды оболочки из конфига не выполняются |

По дороге исправлено десять дефектов — среди них полностью нерабочее SSH-соединение, заливки, способные зависнуть навсегда, и `sync --delete`, рапортовавший об успехе без единого удаления. Полный список — в [changelog](CHANGELOG.md).

## Установка

Поставьте **SyncX** из [маркетплейса](https://marketplace.visualstudio.com/items?itemName=kr-ilya.syncx) или скачайте `.vsix` со [страницы релизов](https://github.com/kr-ilya/vscode-sftp/releases) и выполните `code --install-extension syncx-<version>.vsix`.

Требуется VS Code **1.90** или новее.

> ⚠️ **Стоит и оригинальное расширение?** Оба читают один и тот же `.vscode/sftp.json`, поэтому каждое сохранение заливалось бы дважды. Отключите одно из них для этого воркспейса.

## Быстрый старт

1. Откройте папку, которую нужно синхронизировать.
2. Выполните **SyncX: Config** (`Ctrl+Shift+P` / `Cmd+Shift+P`) и заполните параметры подключения — мастер может проверить их до того, как что-то будет записано.
3. Файлы уже лежат на удалённой стороне? Сначала **SyncX: Download Project**.
4. Работайте и сохраняйте. При `uploadOnSave` больше ничего не требуется.

```jsonc
{
  "name": "My Server",
  "host": "example.com",
  "protocol": "sftp",
  "port": 22,
  "username": "deploy",
  "remotePath": "/srv/www/project",
  "uploadOnSave": true
}
```

Если не указать `password`, его спросят один раз — с предложением запомнить в SecretStorage.

## Конфигурация

Файл лежит в `.vscode/sftp.json` и допускает комментарии и висящие запятые. [Все параметры описаны отдельно](docs/configuration.md); ниже — то, что добавляют чаще всего.

<details>
<summary><b>Заливать по мере изменений, а не только при сохранении</b></summary>

```jsonc
{
  "watcher": {
    "files": "**/*",
    "autoUpload": true,
    "autoDelete": false
  }
}
```

`autoDelete` выключен по умолчанию: VS Code сворачивает удаление папки в одно событие, поэтому единственное событие может означать рекурсивное удаление на удалённой стороне.

</details>

<details>
<summary><b>Несколько удалённых сторон на одну папку</b></summary>

```jsonc
{
  "host": "staging.example.com",
  "username": "deploy",
  "remotePath": "/srv/staging",
  "defaultProfile": "staging",
  "profiles": {
    "staging": { "host": "staging.example.com", "remotePath": "/srv/staging" },
    "production": { "host": "example.com", "remotePath": "/srv/www", "uploadOnSave": false }
  }
}
```

Переключаются командой **SyncX: Set Profile**. Профиль перекрывает верхний уровень, включая `watcher` и `ignore`.

</details>

<details>
<summary><b>Подключение по ключу или через промежуточный узел</b></summary>

```jsonc
{
  "host": "example.com",
  "username": "deploy",
  "remotePath": "/srv/www",
  "privateKeyPath": "~/.ssh/id_ed25519",
  "passphrase": true,

  "hop": [
    { "host": "bastion.example.com", "username": "jump", "privateKeyPath": "~/.ssh/id_ed25519" }
  ]
}
```

`"passphrase": true` означает «спросить», а не «хранить». Всё, что не задано явно, берётся из подходящей секции `~/.ssh/config`.

</details>

<details>
<summary><b>Исключить файлы</b></summary>

```jsonc
{
  "ignore": [".vscode", ".git", ".DS_Store", "node_modules"],
  "ignoreFile": ".gitignore"
}
```

По умолчанию список — `[".vscode", ".git", ".DS_Store"]`, и заданный `ignore` его заменяет, а не дополняет. Шаблоны из `ignoreFile` добавляются к нему. И то и другое применяется до постановки в очередь, поэтому исключённый файл не стоит ничего.

</details>

## Команды

| Команда | |
| --- | --- |
| **Config** | Создать или открыть конфигурацию для этой папки |
| **Set Profile** | Переключить активный профиль |
| **Upload Changed Files** | Всё, что изменилось с последнего коммита — `Ctrl+Alt+U` |
| **Upload / Download Active File · Folder · Project** | Один файл, одна папка или всё целиком |
| **Sync Local → Remote · Remote → Local · Both Directions** | Отразить одну сторону на другую |
| **Diff Active File with Remote** | Сравнить с удалённой версией |
| **List · List Active Folder · List All** | Выбрать удалённый файл и открыть его |
| **Open SSH in Terminal** | Терминал с уже выполненным входом |
| **Cancel All Transfers** | Остановить всё, включая стоящее в очереди |
| **Show Change Detection Diagnostics** | Сколько событий пришло, где отсеяны, сколько залито |
| **Dry Run: Show What Would Be Uploaded** | Весь конвейер вхолостую, без единой передачи |
| **Forget Saved Password** | Убрать пароль из SecretStorage |
| **Reset Confirmed Upload Destinations** | Снова спросить перед следующей заливкой в каждый удалённый путь |

В палитре все они с префиксом **SyncX:**. Большинство есть и в контекстном меню проводника, где зажатый `Alt` заменяет Upload и Download на **Force Upload** и **Force Download** — они игнорируют правила исключений.

Полный справочник: [команды](docs/commands.md) · [конфигурация](docs/configuration.md) · [настройки редактора](docs/setting.md) · [частые вопросы](FAQ.ru.md). Документация в `docs/` — на английском.

## Диагностика

Два канала вывода:

- **SyncX** — операции и ошибки. Отказ называет операцию и удалённый путь, поэтому сообщение выглядит как `mkdir /srv/www/site: Failure`, а не просто `Failure`.
- **SyncX: change detection** — по строке на событие: что залито, что остановлено и почему.

**SyncX: Show Change Detection Diagnostics** показывает счётчики за сессию, а **Dry Run: Show What Would Be Uploaded** прогоняет весь конвейер, не передавая ничего. Вместе они показывают каждое решение вотчера.

Для подробного лога включите `syncx.debug`. Уровень читается при активации, поэтому после изменения перезагрузите окно.

## Ограничения

- **FTP только пассивный.** Транспорт — `basic-ftp`, активного режима у него нет, поэтому `passive: false` сопровождается предупреждением и игнорируется. Активный режим требует, чтобы сервер открыл соединение к вашей машине, чего почти не допускает ни один файрвол.
- **Первый запуск считает, что стороны совпадают.** Пока состояние не записано, SyncX запоминает то, что лежит на диске, и ничего не заливает; настоящее расхождение ждёт явной синхронизации. Заливка целого проекта в живую удалённую сторону при первом запуске необратима.
