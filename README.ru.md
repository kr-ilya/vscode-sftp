# SyncX — SFTP & FTP Sync

**Держит локальную папку и удалённый сервер в согласии, не выходя из VS Code.**
Заливка при сохранении, синхронизация в любую сторону, дерево сервера, сравнение с ним — по SFTP, FTP/FTPS или в локальный путь.

Форк [Natizyskunk/vscode-sftp](https://github.com/Natizyskunk/vscode-sftp) (который сам является форком [liximomo/vscode-sftp](https://github.com/liximomo/vscode-sftp)). Формат `.vscode/sftp.json` тот же, поэтому существующая конфигурация работает без изменений.

---

## Что умеет

| | |
| --- | --- |
| **Передача** | Залить или скачать файл, папку или проект целиком. SFTP, FTP, FTPS или путь на этой же машине. |
| **При сохранении** | `uploadOnSave` отправляет сохранённый файл. `downloadOnOpen` скачивает его при открытии. |
| **При изменении** | Вотчер заливает файлы по мере их изменения и, если попросить, повторяет удаления. |
| **Синхронизация** | Локально → сервер, сервер → локально или в обе стороны, с правилами что пропускать, что обновлять, что удалять. |
| **Из git** | Залить всё, что изменилось с последнего коммита, включая переименования и удаления (`Ctrl+Alt+U`). |
| **Дерево сервера** | Отдельное представление с содержимым сервера: открыть файл, увидеть, какие из них расходятся с вашими. |
| **Сравнение** | Diff открытого файла с его версией на сервере. |
| **Профили** | Несколько серверов на одну папку — staging, production — переключаются из палитры команд. |
| **Несколько корней** | Свой сервер для каждой папки воркспейса и для поддерева внутри одной. |
| **Промежуточные узлы** | Подключение через один или несколько jump-хостов. |
| **Правила исключений** | Glob-шаблоны в конфиге или в отдельном файле, применяются до постановки в очередь. |
| **Аутентификация** | Пароль, приватный ключ, `ssh-agent`, keyboard-interactive. Настройки из `~/.ssh/config` подхватываются. |

## Чем отличается от форка, из которого вырос

| | Оригинал | SyncX |
| --- | --- | --- |
| **Что запускает заливку** | Любое событие файловой системы — включая событие на *каталоге*, что перезаливает всё его содержимое | Событие запускает проверку: исключения → каталог → наша ли это запись → размер/mtime/inode → хеш содержимого. `git checkout` заливает только то, что действительно различается |
| **Личность сервера** | Любой host key принимается молча, защиты от man-in-the-middle нет вовсе | Ключ сверяется с вашим `~/.ssh/known_hosts`; отпечаток показан так, как его печатает OpenSSH; изменившийся ключ — **отказ** |
| **Пароли** | В файле, который вы коммитите | В SecretStorage VS Code, сохраняются только после того, как сработали |
| **Опечатка в `remotePath`** | Деплой уходит туда, куда указывает опечатка | Перед первой заливкой в новое назначение показывается его содержимое и задаётся вопрос — один раз |
| **Обрыв заливки** | Целевой файл обрезается в начале передачи, и при обрыве теряются обе версии | Запись во временный файл и переименование на место |
| **`concurrency: 4`** | Четыре передачи *на операцию* — три операции разом означали двенадцать | Четыре на сервер, сколько бы операций ни шло |
| **Во время передачи** | Крутящийся индикатор | Сколько байт передано и кнопка «Отмена» |
| **Дерево сервера** | Имена файлов | Имена файлов с пометкой, как они соотносятся с вашей копией |
| **Новая конфигурация** | Записывается сразу; работает ли она, вы узнаёте при первой заливке | Мастер, который сначала подключается |
| **Недоверенный воркспейс** | Не объявлен | Объявлен неподдерживаемым; ничего не выполняет команды оболочки из конфига |

По дороге исправлено десять дефектов — среди них полностью нерабочее SSH-соединение, зависавшая навсегда заливка по SFTP, никогда не работавшее переименование и `sync --delete`, рапортовавший об успехе без единого удаления. Список — в [changelog](CHANGELOG.md).

## Установка

**Из маркетплейса** — найдите *SyncX* во вкладке Extensions или выполните:

```
ext install kr-ilya.syncx
```

**Из файла** — к каждому [релизу](https://github.com/kr-ilya/vscode-sftp/releases) приложен `.vsix`:

```
code --install-extension syncx-1.0.0.vsix
```

Нужен VS Code **1.90** или новее.

> **Ставите оба расширения?**
> SyncX и оригинал уживаются вместе — у них разные команды, представления и настройки, — но **оба читают один и тот же `.vscode/sftp.json`**. Если в одной папке включены оба, каждое сохранение заливается дважды. Отключите одно из них для этого воркспейса.

## С чего начать

1. Откройте папку, которую нужно синхронизировать.
2. Выполните **SyncX: Config** (`Ctrl+Shift+P` / `Cmd+Shift+P`).
3. Заполните параметры подключения — мастер может проверить их до того, как что-то будет записано.
4. Файлы уже лежат на сервере? Сначала **SyncX: Download Project**.
5. Работайте. При `uploadOnSave` сохранение отправляет файл.

Конфигурация появится в `.vscode/sftp.json`; она допускает комментарии и висящие запятые:

```jsonc
{
  "name": "My Server",
  "host": "example.com",
  "protocol": "sftp",
  "port": 22,
  "username": "deploy",
  "remotePath": "/srv/www/project",
  "uploadOnSave": true
}
```

Если не указать `password`, его спросят — с предложением запомнить в SecretStorage.

<details>
<summary><b>Заливать по мере изменений, а не только при сохранении</b></summary>

```jsonc
{
  "watcher": {
    "files": "**/*",
    "autoUpload": true,
    "autoDelete": false
  }
}
```

`autoDelete` выключен по умолчанию: VS Code сворачивает удаление папки в одно событие, поэтому единственное событие может означать рекурсивное удаление на сервере.

</details>

<details>
<summary><b>Несколько серверов на одну папку</b></summary>

```jsonc
{
  "host": "staging.example.com",
  "username": "deploy",
  "remotePath": "/srv/staging",
  "defaultProfile": "staging",
  "profiles": {
    "staging": { "host": "staging.example.com", "remotePath": "/srv/staging" },
    "production": { "host": "example.com", "remotePath": "/srv/www", "uploadOnSave": false }
  }
}
```

Переключаются командой **SyncX: Set Profile**. Профиль перекрывает верхний уровень, включая `watcher` и `ignore`.

</details>

<details>
<summary><b>Подключение по ключу или через jump-хост</b></summary>

```jsonc
{
  "host": "example.com",
  "username": "deploy",
  "remotePath": "/srv/www",
  "privateKeyPath": "~/.ssh/id_ed25519",
  "passphrase": true,

  "hop": [
    { "host": "bastion.example.com", "username": "jump", "privateKeyPath": "~/.ssh/id_ed25519" }
  ]
}
```

`"passphrase": true` означает «спросить», а не «хранить». Всё, что не задано явно, берётся из подходящей секции `~/.ssh/config`.

</details>

## Команды

| Команда | |
| --- | --- |
| **Config** | Создать или открыть конфигурацию для этой папки |
| **Set Profile** | Переключить активный профиль |
| **Upload Changed Files** | Всё, что изменилось с последнего коммита — `Ctrl+Alt+U` |
| **Upload / Download Active File · Folder · Project** | Один файл, одна папка или всё целиком |
| **Sync Local → Remote · Remote → Local · Both Directions** | Отразить одну сторону на другую |
| **Diff Active File with Remote** | Сравнить с версией на сервере |
| **List · List Active Folder · List All** | Выбрать файл на сервере и открыть его |
| **Open SSH in Terminal** | Терминал с уже выполненным входом |
| **Cancel All Transfers** | Остановить всё, включая стоящее в очереди |
| **Show Change Detection Diagnostics** | Сколько событий пришло, где отсеяны, сколько залито |
| **Dry Run: Show What Would Be Uploaded** | Весь конвейер вхолостую, без единой передачи |
| **Forget Saved Password** | Убрать пароль из SecretStorage |
| **Reset Confirmed Upload Destinations** | Снова спросить перед следующей заливкой в каждое назначение |

В палитре все они с префиксом **SyncX:**. Большинство есть и в контекстном меню проводника, где зажатый `Alt` заменяет Upload и Download на **Force Upload** и **Force Download** — они игнорируют правила исключений.

## Если что-то идёт не так

Два канала вывода:

- **syncx** — операции и ошибки.
- **SyncX: change detection** — по строке на событие: что залито, что остановлено и почему.

`SyncX: Show Change Detection Diagnostics` показывает счётчики, а `Dry Run` — что *было бы* отправлено, ничего не отправляя. Вместе они превращают вопрос «почему оно это залило» из гадания в проверяемый. Для подробного лога включите `syncx.debug`; уровень читается при активации, поэтому после изменения перезагрузите окно.

## Ограничения

- **FTP только пассивный.** Транспорт — `basic-ftp`, активного режима у него нет, поэтому `passive: false` сопровождается предупреждением и игнорируется. Активный режим требует, чтобы сервер открыл соединение к вашей машине, чего почти не допускает ни один файрвол.
- **Первый запуск считает, что сервер совпадает.** Пока состояние не записано, SyncX запоминает то, что лежит на диске, и ничего не заливает. Настоящее расхождение ждёт явной синхронизации: бездействие обратимо, перезапись живого сервера — нет.
- **Не реализовано:** версионные бэкапы, генерация SSH-ключей, drag-and-drop с разрешением конфликтов, эскалация через `su`, локализация интерфейса.
